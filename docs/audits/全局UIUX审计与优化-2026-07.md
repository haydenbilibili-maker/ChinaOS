## 2. 关键发现与处置

### P0-01 · 移动抽屉焦点可逃逸（已修复）

**证据**：`Shell.jsx` 原有抽屉开关和 Esc 关闭，但打开后未把焦点移入导航、未约束 Tab，也未在关闭后归还触发按钮。键盘用户可能把焦点移到遮罩后的主内容。

**处置**：增加抽屉触发器/侧栏引用、打开时聚焦当前导航项、首尾 Tab 循环、关闭后焦点归还；补 `aria-controls`、`aria-expanded`、主导航标签和可聚焦“跳到主内容”入口。

### P0-02 · 全局搜索关闭后焦点丢失（已修复）

**证据**：搜索面板已有 `role="dialog"`、自动聚焦输入和 Esc，但没有焦点循环、焦点归还和可见关闭按钮。

**处置**：增加模态焦点闭环、关闭后恢复原触发点、`aria-label` 与显式关闭按钮。加载中、无结果仍保留既有可感知反馈。

### P1-01 · 窄侧栏反而展开全部模块（已修复）

**证据**：原 `showModules = alwaysShowModules || expanded || narrow`，窄栏会渲染全部 279 个模块图标；标签隐藏后只剩超长图标列，分类意义丢失。

**处置**：窄栏仅保留一级分组入口和首页快捷项；点击分组恢复宽栏并展开目标组。当前组仍由路由自动维持展开。

### P1-02 · Tab 指示器响应式错位（已修复）

**证据**：共享 `TabBar` 只在 value 变化时测量，窗口缩放、字体回流、横向滚动不会重新定位。

**处置**：用 `ResizeObserver` 监听 TabBar 与按钮尺寸，监听横滚并把活动 Tab 自动滚入可视区；键盘方向键、Home/End 与 reduced-motion 契约保持不变。

### P1-03 · 无限阴影呼吸消耗过高（已修复）

**证据**：共享看板 hero 和 screen card 长期执行阴影/边框动画，多个卡片同时存在时会增加持续绘制，且视觉层级被“所有卡都在呼吸”稀释。

**处置**：停止 hero 与 screen card 的无限阴影动画，保留 hover、选中、短时数据变化和小型 live dot 等有语义反馈；`prefers-reduced-motion` 继续全局兜底。

### P1-04 · 390px 触控与图表空间不足（已修复）

**处置**：共享控件增加最小高度令牌；移动顶栏按钮最小 40px；图表面板在 768px 以下改用 `clamp(220px, 42vh, 300px)`；390px 面包屑限制宽度，长标题保持截断而不挤压操作区。

### P1-05 · 史鉴 iframe 手机首屏过满（已修复）

**处置**：768px 与 420px 分别收紧 iframe 高度与最小高度，让页眉、直接打开入口和卷页内容保持可发现；不修改 iframe 内部史册皮肤、内容或交互协议。

### P1-06 · 长表缺共享横滚契约（已修复）

**处置**：新增 `.os-table-scroll`，保留 table 语义和列宽，提供横向滚动、触控惯性与 overscroll 边界；旧页面的移动兜底继续有效，后续高流量长表可逐步套用该容器。

## 4. 关键前后对比

- **侧栏窄态**：全部模块图标长列 → 一级分组导航，点击后恢复完整上下文。
- **移动抽屉**：视觉遮罩但焦点可穿透 → 焦点进入、循环、Esc 关闭并归还。
- **搜索**：只能靠 Esc/点遮罩关闭 → 显式关闭按钮 + 完整模态焦点管理。
- **Tab**：首次测量后可能错位 → 缩放、横滚、字体回流持续同步。
- **动效**：多个大卡持续阴影呼吸 → 静态层级为主，反馈只在交互/状态变化发生。
- **手机首屏**：图表和史鉴 iframe 容器偏高 → 视口约束化，标题、控制和内容更平衡。
