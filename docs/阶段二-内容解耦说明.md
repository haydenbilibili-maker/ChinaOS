# 阶段二 · 内容解耦说明 · China OS

> 目标：把「内容型」专题 Tab 的 HTML 从 26k 行巨石 `china.html` 外移成独立、可 diff、
> 可定点编辑的小文件，为后续乱码重写铺路。**运行行为零改动，已用浏览器实地验证。**

## 一、做了什么

- 把 **11 个纯静态、可达的内容型 `getXxxHTML()`** 函数体外移到 `tabs/<slug>.html`：
  `ecology · automotive · culture · dataElement · bri · foreignTrade · digital ·
   urban · civilAviation · private · foodSecurity`
- 这 11 个函数在 `china.html` 中变薄为：`function getXxxHTML(){ return TAB_PARTIALS['slug']; }`
- `china.html` 内新增一个**生成的** `TAB_PARTIALS` 块（带 `BEGIN/END` 标记），
  把各 tab 内容内联进来——保证 `file://` 与 `http` 下都能同步返回字符串、行为不变。
- `china.html` 体积 26431 → 24833 行。

## 二、单一数据源与构建

- **内容的唯一真源 = `tabs/<slug>.html`。** 改内容只改这些文件，**不要手改** `china.html`
  里的 `TAB_PARTIALS` 块（它是生成物）。
- 改完跑构建把内容重新内联回 `china.html`：

  ```bash
  python3 scripts/build_china.py          # 从 tabs/ 重建 TAB_PARTIALS 块（幂等）
  python3 scripts/build_china.py check    # 校验 china.html 与 tabs/ 是否同步（CI/钩子用）
  python3 scripts/build_china.py explode  # 一次性外移（已执行，勿重复跑）
  ```

## 三、为什么内容会「出现两份」

内联设计下，每个 tab 的内容同时存在于 `tabs/<slug>.html`（源）与 `china.html` 的
`TAB_PARTIALS`（生成的内联副本）。这是为兼容 `file://` 直接打开而做的取舍，类似打包产物。
因此乱码扫描总数从 691 升到 702（多出的 11 行 = 11 个 tab 各压成 1 行 JSON 的内联副本）。
**唯一内容仍是 691 行**：`tabs/`(410) + `china.html` 非 tab 区(281)。

## 四、对乱码重写的意义

- 70% 乱码（410/691）现已落在 11 个**独立小文件**里，重写时：
  1. 直接编辑 `tabs/<slug>.html`（依《中国深度调研系列_索引与恢复指令.md》重写文案）；
  2. `python3 scripts/build_china.py` 重建；
  3. `python3 scripts/scan_mojibake.py --json mojibake_report.json` 看计数下降，
     基线自动收紧、防回潮。
- 剩余 30% 乱码分布：图表 init 代码 86 行、顶层数据/注释 103 行、
  **死代码** `getGuochaoHTML`(44) / `getDiplomacyHTML`(31) 共 75 行——后者建议直接删除
  （已并入 `culture` / `diplomacyGlobal`，0 调用）。
